# High-priority Google AI Studio project instructions

Read this file before every change, together with AGENTS.md, GEMINI.md, AI_HANDOFF.md and PROJECT_STATUS.json. These are persistent repository instructions. Also paste this policy into the project's Google AI Studio system instructions; a repository file does not itself configure AI Studio memory.

1. Fetch GitHub first. Record the latest main SHA, current branch and git status. Preserve uncommitted work. Use a separate branch and a pull request; do not publish directly to main. Never replace main with a partial web-preview export. If the integration cannot use a separate branch, stop publication and provide a reviewable patch.
2. A file missing from AI Studio's preview is NOT a deletion request. Preserve package-lock.json and EVERY tracked build/ file, including the icon, NSIS include, runtime setup, packaging hooks, PE validator and evidence gates. Preserve native helpers, Electron settings, browser companion assets and existing source files. Fetch the full repository if needed; stop publishing if a complete checkout cannot be obtained.
3. Before publishing, inspect `git diff --name-status` and specifically `git diff --diff-filter=D --name-only`. Restore unintended deletions from the last verified commit. If package.json dependencies did not change, do not regenerate the lockfile or alter dependency versions. Never fix CI by disabling a check or supplying fake binaries.
4. Production starts without sample people, residents, licenses, rooms, hires, schedules or operational measurements. Missing facts remain unknown. Never invent vitals, clinical stability, census, staffing hours, dates, phone numbers, policy approvals, actions taken or regulatory compliance. Drafts must disclose missing facts and require human review. Heuristics/templates are not validated AI conclusions.
5. All Demo reads AND writes, canonical tasks, metadata, reminders and copied output must respect the selected isolated Demo workspace and be labeled. Demo mode must never call live-store methods accidentally. Use real Core/SQLite/IPC/HTTP regression tests, not only mocks that hide integration defects. Supply synthetic test fixtures explicitly; do not make Production auto-seed so a test passes.
6. Preserve DPAPI vaults, encrypted databases, settings, model files, ShareSync contracts, clinical review gates, provider isolation, HIPAA/Local Only and permission boundaries. Do not export secrets/PHI, read saved passwords, weaken privacy for browser audio, silently delete legacy records, rotate keys or rewrite published history. Use local speech output only when the voice is explicitly local.
7. Run clean locked installation, all tests, hardening, syntax, repository policy, production audit and relevant browser/UI tests. Run release checks with genuine generated inputs; use GitHub Actions for unavailable toolchains. Inspect the exact pushed commit's runs/logs. Do not publish a known failing change or claim skipped checks passed.
8. Update the handoff/status with the base SHA, actual changes, exact results and remaining limitations. Source tests do not establish Windows installer/upgrade, real-data clinical, account or speaker acceptance. Preserve working features and make small logical commits; no unrelated rewrite.

Incident reference: main `a5d22b623c5c49fccd36b41bd4488d2a64fac346` deleted the lockfile and nine required build assets. Run 36640248873 failed before regression tests could start. The same update introduced production sample seeding and fabricated operational drafts. Treat these as regression examples, not patterns to repeat.
