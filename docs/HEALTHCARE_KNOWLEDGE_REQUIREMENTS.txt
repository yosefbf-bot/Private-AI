PRIVATE AI — MAJOR HEALTHCARE KNOWLEDGE ENGINE UPDATE

IMPORTANT:
This is an upgrade to the EXISTING Private AI application and codebase. Do not restart the application from scratch and do not replace working existing functionality unnecessarily.

Preserve the current Private AI architecture, installer approach, HIPAA controls, local/cloud AI modes, Projects, File Library, Agents, Automations, background Worker, ShareSync support, chat interface, local model support, OpenAI API support, and existing user preferences.

The purpose of this update is to add a comprehensive Healthcare Knowledge Engine that makes Private AI highly capable for:

- Nursing-home administration
- Skilled nursing facility operations
- Federal nursing-home regulation

- Survey preparation and deficiency analysis
- MDS / RAI / PDPM

======================================================================
1. CORE DESIGN PRINCIPLE
======================================================================

DO NOT attempt to make the local AI model memorize healthcare knowledge through retraining.

Keep the local brain as a general reasoning model.

Healthcare specialization should primarily be implemented through:

RAG — Retrieval-Augmented Generation

The workflow should be:

User question
→ determine question type
→ determine relevant knowledge domains
→ search Healthcare Knowledge Engine
→ retrieve authoritative passages
→ provide retrieved passages to AI brain
→ AI reasons over sources
→ answer
→ display citations/source information

The system should use:

KNOWLEDGE = curated database / RAG

REASONING = local model or OpenAI model

USER WORK STYLE = instructions, examples and possibly fine-tuning later

Do not use model fine-tuning simply to memorize regulations, clinical guidelines or medication information that can change over time.

5. SOURCE HIERARCHY
======================================================================

Private AI should understand that healthcare sources have different authority.

Build source-ranking metadata into the retrieval system.

For regulatory/nursing-home questions, generally prefer:

1. Applicable law / regulation
2. CMS official guidance
3. State law / regulation
4. NYSDOH official guidance
5. Other government guidance
6. Current recognized professional clinical guidelines
7. FDA / official medication information where applicable
8. Facility / corporate policies
9. Other authoritative clinical references
10. General AI model knowledge

For medication questions, generally prefer:

1. FDA / official drug labeling
2. DailyMed / official drug information
3. Major recognized clinical guidelines
4. Government medical references
5. recognized professional references
6. facility protocols
7. model knowledge

Do not blindly merge conflicting sources.

If relevant sources disagree, identify the difference.

Example:

"Federal regulation requires X; the facility policy is more restrictive and requires Y."

7. VERSION CONTROL
======================================================================

Healthcare guidance changes frequently.

The Knowledge Engine must be version aware.

Private AI should normally retrieve:

CURRENT
+
EFFECTIVE

references.

Superseded material should not be treated as current unless requested.

However, retain older versions so historical questions can be answered.

Example:

"What requirement was in effect when this survey occurred in February 2025?"

The Knowledge Engine should retrieve the version that was effective at that time when possible.

The UI should clearly label:

CURRENT

SUPERSEDED

ARCHIVED

38. FINAL DESIGN GOAL
======================================================================

Private AI should evolve from:

"a general AI assistant that can read healthcare documents"

into:

"a healthcare-aware AI platform with authoritative nursing-home, regulatory, clinical and medication knowledge."

The AI brain should NOT need to memorize healthcare knowledge.

The Healthcare Knowledge Engine should supply current, authoritative information to whichever reasoning model is being used.

The final architecture should effectively be:

PRIVATE AI

→ Chat / Projects / Agents / Automations

→ Healthcare Knowledge Engine

→ Federal / CMS Knowledge
→ NY / NYSDOH Knowledge
→ MDS / PDPM Knowledge
→ Clinical Medicine Knowledge
→ Medication / Pharmacology Knowledge
→ Facility / Corporate Knowledge
→ Project Knowledge

→ Resident / PHI Context when applicable

→ Local Brain or OpenAI Reasoning

→ Answer + evidence + citations + model/source transparency

This should feel completely integrated into Private AI rather than like a separate healthcare module bolted onto the side.

Preserve the existing clean ChatGPT-style interface and existing application design while adding this functionality in a way that is powerful but simple for the user.
