Private AI 2.1.3 — local model loading fix

The newer recording shows Qwen refused with LOW_MEMORY at about 4.8 GB available, and Llama changing from loading to CANCELLED. These are separate issues from the screen-refresh error fixed in 2.1.2. A Microsoft runtime installation would not resolve either recorded error.

What changed

  • Startup no longer counts as idle. The old maintenance timer could stop a manually loaded model before it became ready because its last-use timestamp was still zero. Idle cleanup now applies only to a ready, unused model.
  • Corrected RAM estimate. At the default 4096-token context, both included model choices pass the estimate with the 4.8 GB available shown in the recording. The budget includes model size, working headroom, and a conservative context-cache allowance. It remains an estimate; the app still stops the model if available RAM falls below 1 GiB.
  • Honest cancellation and memory errors. A memory-pressure stop stays a LOW_MEMORY error. Unload cancels startup; a late health response cannot make a stopped model appear ready. Changing the selected model clears an old model's error.
  • No Microsoft setup step. The Windows engine is rebuilt from the same pinned llama.cpp source with compiler-runtime support linked into its files. The package includes both a baseline x64 CPU backend and an AVX2 backend, selected automatically. It needs no separate Visual C++ Redistributable installation. The old Microsoft runtime setup button is removed.

Upgrade

  1. Quit Private AI, including its tray icon.
  2. Extract the installer ZIP into a new folder. Run Installer/PrivateAI-Setup-2.1.3-x64.exe under your usual Windows account. The installer is configured for your account without elevation. For portable use, extract the separate portable ZIP into a new local folder and open Portable/PrivateAI.exe.
  3. Open AI Processing. Select either existing model, then click Load model once and wait for ready. Loading may take a few minutes. Selecting a model does not itself load it.
  4. For an initial test without API credits, select Local Only, save processing settings, and ask a short question in a new chat.

Keep your downloaded model files and PrivateAI2 data folder. No model redownload or Microsoft runtime repair is required for this update. Run only one app copy at a time. The installer and portable app share the current Windows account's existing data.

If RAM is lower because other programs are open, close heavy programs, set Local context tokens to 2048, save, and retry. Llama is the smaller model. The app cannot create additional RAM or override your organization's application-control policy.

Validation and limits

128 regression tests and 22 Chromium UI checks passed. Real Qwen and Llama inference at context 4096 passed on Linux with the corrected manual-load lifecycle, including remaining ready through the maintenance timer, with zero OpenAI requests. Windows engine inspection verifies x64 architecture, every bundled DLL dependency and imported symbol, baseline/AVX2 backends, and absence of external compiler-runtime DLL requirements. Installer archive and delivery ZIP integrity are checked separately.

The Windows executable could not be run in this environment: the available Wine runtime requires Unix sockets that this environment does not permit. Linux inference and static Windows checks do not replace execution on your PC. See Validation/startup-inference.json and Validation/runtime-check.json for the exact evidence.

Private AI 2.1.1 — additional local brain

Built with Llama.

This update adds Llama 3.2 3B Instruct Q4_K_M alongside Qwen3-4B Q4_K_M. This is a pretrained Meta model converted to GGUF by bartowski, not a newly trained model. The optional download is 2,019,377,696 bytes (about 2.02 GB). It is pinned to a specific revision and SHA-256 checksum.

Use it

  1. Quit Private AI, including the tray icon, and run the new 2.1.1 installer over the existing installation. Do not delete the app's data folder. Portable users should extract the new portable download into a separate folder and run only one copy.
  2. Open AI Processing → Local Brain.
  3. Click Use / download Llama 3.2 3B Q4_K_M. Review the included license and Acceptable Use Policy, then accept if appropriate. You can cancel and continue using Qwen.
  4. Wait for downloading/verification. The model becomes the selected model automatically when no inference is running. Its path appears on the page. If a task is running, wait for it and choose the downloaded GGUF afterward.
  5. For zero OpenAI calls, select Local Only. Try a short document summary with synthetic text.

You may keep both models downloaded. Use either model button to verify and select that model without downloading it again, or use Choose a GGUF file. Normal model downloads live under %LOCALAPPDATA%\PrivateAIModels. Switching does not delete either model, your chats, or your settings. Only one model runs at a time; existing memory protections and five-minute idle unloading still apply.

The app uses the GGUF's chat template. Qwen-specific thinking controls are applied only to a Qwen-named file, so Llama does not receive the Qwen /no_think marker. Changing models changes reasoning behavior, not computer permissions or tools. No new WhatsApp capabilities are part of this update.

Download failures

A truncated or incorrect download is rejected and the partial file is removed. An already-existing file is rechecked before selection. A damaged existing file is preserved; move that model file aside and retry the download, or select a known-good GGUF. Do not delete PrivateAI2 or its encrypted data to fix a model download.

Private AI 2.1.1 — Hybrid upgrade evaluation

This is an in-place upgrade of 2.0.1. It retains the Windows startup fix, encrypted database, Windows-protected key, 90-day default retention, report folder, manual Chrome capture, and existing OpenAI connection. No data reset is required.

Upgrade and start

  1. Close Private AI, including its tray icon. Extract the installer ZIP and run Installer/PrivateAI-Setup-2.1.1-x64.exe using the same Windows account and installation folder. Do not uninstall or delete %LOCALAPPDATA%\PrivateAI2.
  2. Open AI Processing. Smart Hybrid is the default. Select Local Only if you want every OpenAI call blocked. Existing API keys/settings remain saved.
  3. The CPU inference runtime is bundled. Download Qwen3-4B Q4_K_M with the app's button (about 2.50 GB), or select a compatible GGUF model you already have. Downloading is optional. The pinned default model's checksum is verified. Its Apache-2.0 license and publisher are linked below.
  4. Model files downloaded by the app live in %LOCALAPPDATA%\PrivateAIModels, outside normal program updates. They contain public model weights, not chat history. Models load on demand and unload after five idle minutes. Balanced mode limits CPU use. RAM pressure unloads the model; only one local inference request runs at a time.
  5. In Worker, enable background jobs and optional start-at-sign-in if wanted. Windows must remain signed in and awake. Closing the app window keeps an enabled Worker or messaging bridge running; Quit stops it. A system restart requires Windows sign-in again.
  6. Run Settings → Run local checks, then try /calc (120 + 30) * 4. Test real work only after the Windows checks and your organization's review.

The portable download is an alternative, not another user account. Extract it to a separate local folder and run Portable/PrivateAI.exe. Both forms use the same account's existing encrypted data; run one at a time.

What works locally

  • /calc 120 * 4 — arithmetic with no LLM or API call.
  • /extract — return the text of attached documents without inference.
  • /unread or “Check today's unread emails” — list up to 50 unread classic Outlook messages after granting access in Apps.
  • /calendar today or /calendar tomorrow — retrieve a date's classic Outlook appointments after permission is granted. Appointments are sorted and timed overlaps are flagged. Meetings are not moved automatically.
  • /status — Worker/model status, without an API call.
  • /report NAME — run an explicitly configured browser report workflow and save the download to your approved work folder.
  • Ordinary questions/documents use your selected processing mode. The local model can summarize and explain short text. Images, overly large context, freshness-sensitive requests, and high-stakes reasoning may require cloud processing. In Local Only, unsupported tasks stop or receive an explicitly unverified local draft; no cloud request is made.

The local model does not receive arbitrary shell/computer-control tools. Commands embedded in documents and pages are not executed. Existing Apps and folder permissions continue to control access.

Reliability and API usage

Scores are validation heuristics, not probabilities or guaranteed accuracy. Local answers are checked for source quotations, matching numerical tokens, missing context, and available tool results. This does not independently prove that every interpretation is correct. Cloud answers are labeled as requiring review rather than assigned an invented accuracy score.

API Usage shows measured local tasks, cloud attempts, provider token counts, and daily/weekly/monthly totals within retained history. Configure your exact model's input, cached-input, and output rates to get token-cost estimates. Unknown prices and failed requests with unknown usage remain explicitly unknown. Tool/search charges are excluded. Local-model tokens are not OpenAI tokens. Dollar savings and counterfactual API calls avoided are not fabricated.

The existing bounded document/context preparation remains in use. This is not a full retrieval/indexing system for arbitrary hundreds-of-page files; excessive inputs are rejected rather than silently truncated.

Browser report workflows

Browser reports use a separate local Edge profile. You sign in yourself. No account credentials are embedded in a workflow. Add an HTTPS report URL, a precise download-button selector, and any reviewed fill/click/wait steps. Additional trusted origins may be needed for your site's sign-in flow. The workflow stops if a selector is ambiguous, navigation leaves those origins, or the expected download does not appear. Setup depends on the reporting website; no facility-specific workflow has been validated here.

Only document formats are saved, under the selected report folder. A report-browser task unloads the local model; inference does not run alongside that heavy workflow. The Chrome Companion remains manual and is not used to scan ordinary pages automatically.

WhatsApp setup and limits

Messaging is optional and starts disabled. It is experimental because WhatsApp's interface can change.

  1. In Messaging, open WhatsApp Web, sign in yourself, and select your dedicated group. This uses a separate local Edge window/profile. Keep it open.
  2. Send a harmless message from your phone. Verify the open group and choose the stable sender ID belonging to your trusted account. Display names are not used for authorization.
  3. Review the privacy warning and select the permissions you want. Copy the displayed command example, which includes the prefix, this PC's command code, and /status.
  4. Enable the bridge, wait a few seconds for its initial baseline, and send a new command. Existing messages are ignored. Each PC has its own command code.
  5. Response text is off by default; enable it if approved. Documents stay in the report/ShareSync folder. Attachment sending is not implemented/enabled in this release. Task chats remain encrypted in Private AI and follow retention.
  6. Background access while the app is locked requires its separate checkbox. This permits only the bridge's approved tasks; it does not unlock the desktop interface. Disable the bridge to stop new remote work. An action already underway may have completed.

Windows-app limitation: native intake is capability-gated. It works only when the selected WhatsApp process exposes stable group/message identifiers through Windows accessibility. If those identifiers are unavailable, the app refuses to infer identity from displayed names; use Web intake. Automatic replies currently use the separately connected Web fallback. Desktop-only automatic sending is not implemented.

Before sending a reply, the Web adapter verifies the group identity/header. If delivery cannot be confirmed, the bridge disables itself and does not retry. On-PC pairing and actual WhatsApp delivery have not been tested here. Treat a failed/uncertain status as a reason to inspect the group before repeating a command.

Optional forwarding of desktop results applies when the Private AI window is not focused. Use the global setting or the per-task choice below the chat box. The bridge and response-text permission still apply. Started, completion, and failure notices are configurable. Continuous progress updates are not implemented.

Privacy boundary

OpenAI traffic uses HTTPS. Local inference uses an authenticated random loopback port bound to 127.0.0.1; it is not exposed to the LAN and does not use TLS. The Chrome native connection remains the existing protected local connection. Multiple PCs maintain separate keys, ports, and databases.

No API keys, WhatsApp profiles/cookies, or live databases go into ShareSync. Normal diagnostics exclude message bodies. Encrypted app records, usage records, and outbound-message records follow local retention. WhatsApp and ShareSync have their own retention/version policies; app cleanup cannot remove every external copy. Keeping WhatsApp open consumes additional RAM, and the model checks available memory before loading.

Installing this application, encryption, or disappearing messages does not establish HIPAA suitability. Your organization's approvals and provider/channel requirements still apply.

Private AI 2.0.1 — Windows startup fix

Install the fix

  1. Close Private AI, including its system-tray icon if present.
  2. Extract the complete new ZIP. Run Installer/PrivateAI-Setup-2.0.1-x64.exe under the same Windows account and choose your existing installation folder. You do not need to uninstall first.
  3. Open Private AI. In Settings, run Run local checks.

For portable use, extract to a new local folder and run its Portable/PrivateAI.exe. Keep all neighboring files. Use only one installed or portable copy at a time.

Both versions use the existing %LOCALAPPDATA%\PrivateAI2 data folder. Do not delete, rename, or move this folder or vault.dpapi as a troubleshooting step. The upgrade keeps the same database format and key location; no reset or data migration is needed. Your chosen report folder and 90-day retention setting remain as saved.

If startup still fails, send a screenshot of the new diagnostic code. It identifies the startup stage without displaying paths, account names, keys, or chat content. A missing encryption key with an existing database now stops safely instead of creating a replacement key.

What was corrected

Version 2.0.0 wrote a temporary file, reopened it with read-only access, and called fsyncSync. On Windows, the underlying FlushFileBuffers operation requires a writable file handle. First-run creation of vault.dpapi could therefore produce the reported generic storage error. The same utility is used for some other saved files.

The utility now creates the temporary file with exclusive write access, writes and flushes through that handle, closes it, and then replaces the destination. Write, flush, or replacement failures leave the existing destination intact and attempt temporary-file cleanup. Encryption and folder permission checks remain enabled.

Reference: Microsoft FlushFileBuffers documentation.

Validation and limits

The original code failed the new first-run and replacement regression cases under simulated Windows file-handle rules. The corrected code passes those cases, failure-injection checks, encrypted-key lifecycle checks, and the existing regression suite. Tests use synthetic data. See Validation/test-results.txt and Validation/startup-before-fix.txt for results.

The executable and bundled runtimes come from the original 2.0.0 release; application code and installer are repackaged as 2.0.1. Packaged source is checked against the corrected source. This environment cannot execute the application on your actual Windows profile, so Windows launch, DPAPI, and organization-specific policies still need the local check above. The package remains unsigned.

This release fixes startup in the released 2.0.0 package. It does not include the separate, unfinished remote-command additions discussed later.

Set up once, then open and chat

Installation and first test

Extract the complete package to a local disk folder. Run the installer under your normal Windows account, or run Portable/PrivateAI.exe. Both use %LOCALAPPDATA%\PrivateAI2 for private data. Use one installation at a time per Windows profile. The app takes a per-profile single-instance lock; installer and portable copies are not separate accounts.

The installer is unsigned. Your organization may block it. Do not lower Windows security settings or bypass your organization's controls. IT should inspect the included source, hashes, test report, and binaries. Re-running the installer repairs application files without intentionally removing private data. Uninstallation keeps private data.

Open Settings: save the approved API key, load available models or enter an approved model ID, choose a report work folder, review HIPAA and retention options, and save settings. The approval checkbox is an attestation, not automatic verification. Replacing the key or changing API project/organization revokes this confirmation.

Run local checks. They use synthetic data, no OpenAI requests. They test Windows encryption, private folder ACL, encrypted SQLite backup/cleanup, the local bridge, the bundled app-access helper, file formats, report-folder write/cleanup, and audit-chain integrity. Separately test your API connection and one synthetic chat; generation may incur API charges.

Daily chat

New Chat creates persistent local history; Temporary Chat does not save chat or imported working files to the app database. Copy, edit/regenerate, stop, and export are available. An explicit export from any chat creates a normal document that remains until removed. Explicitly saving a temporary chat stores it as persistent history.

Attach only the files needed for your question. Supported references: text, Markdown, CSV, text-based PDF, DOCX, XLSX, PNG/JPEG/WebP, EML, MSG, and ICS. Email attachments are not analyzed. Save and attach an email attachment separately if required. Scanned/image-only PDFs need external, organization-approved OCR first. Encrypted files, macros, legacy DOC/XLS, audio, and arbitrary code execution are not supported. Typical limits: 20 MB per file, six attachments per request, 300 PDF pages, 350,000 extracted characters, and 90,000 request-context characters by default. A large image request has an additional 40 MB serialized-request ceiling.

Save an answer as Word, PDF, Markdown, text, Excel, or CSV. Excel/CSV export requires a Markdown table in the answer. Formulas remain text; ordinary safe numeric cells become numbers. Review dates, leading-zero identifiers, totals, and source facts. Reports get unique generic filenames to avoid collisions and PHI-bearing filenames. Open the report to confirm appearance in your actual Office/PDF app.

Projects hold instructions and related chats. Memory is explicit and off by default, with its own expiry. Agents are reusable report prompts and selected file snapshots, not unrestricted computer-use agents.

Chrome — manual page reads only

Settings → Connect Chrome opens the included extension directory. In chrome://extensions, enable Developer mode, Load unpacked, select that directory, and pin the extension. Your administrator may need to allow an unpacked extension and native messaging. The expected ID is joamalncafnpildccchmddldboiefphl; do not regenerate its public key.

Opening the panel or sending an ordinary question does not query the tab or extract its page. To read a page, click the toolbar icon on that tab, select Include this page or selection only, and send. Only that attempt reads the chosen content. The checkbox resets even if extraction fails. Old page snapshots are not automatically attached to future follow-up requests, though previous answers remain conversation context. No automatic rereads, browsing, link following, DOM watchers, or page actions are present. Chrome's own pages, PDF viewer, protected pages, cross-origin frames, and certain sites cannot be captured; use selected/copied text or a local file instead.

Chrome has no API key. The included native bridge uses this Windows profile's app and secrets. If the panel cannot connect, open/unlock the desktop app, reconnect Chrome in Settings, reload the extension, and check your organization's policy. If you move the portable folder, reconnect Chrome and update its unpacked-extension location. Never move the whole private-data folder into ShareSync.

Outlook, WhatsApp, other programs, and folders

Under Apps, independently allow Outlook message reading, calendar reading, draft creation, and appointment creation. Direct integration requires classic Outlook and a configured profile. Message browsing reads only headers for up to 50 recent default Inbox items; choosing one reads its plain body, without attachments. Calendar reading uses the default calendar, a user-selected range of up to 31 days, and up to 200 overlapping events. Dates/times use the PC's local timezone. No shared mailbox picker or attendee/invitation workflow is included. Drafts and appointments are saved/displayed in Outlook after a native confirmation; no Send call exists. Outlook may display its own profile/security prompts. If a write times out, inspect Outlook before retrying to avoid a duplicate.

For WhatsApp or another program: open it, choose Choose an open app, explicitly enable read/write permissions, and later choose Read visible text or Write a draft. The exact executable is hash-pinned; after an app update, choose it again. Screen reads use visible Windows accessibility content, not screenshots or hidden conversations. Draft writes only use an exposed writable text field selected by the user, and replace its current value after confirmation. There are no injected keystrokes, mouse actions, Send clicks, clipboard reads, elevation bypasses, or model-driven computer actions. Some apps expose no usable text/fields; use copy/paste instead. A permission grant is not a HIPAA approval for that app or account. Do not use WhatsApp for PHI unless your organization has expressly approved the particular service and workflow.

Allowed folders have separate read/write grants. Browse reads the selected directory only, not a recursive index; choose a file to import it. Existing originals stay untouched unless you explicitly edit a TXT/MD file and confirm. Version checks reject stale edits, and creating a new note never overwrites an existing filename. Concurrent changes across ShareSync replicas can still create vendor conflict copies—review those normally. New DOCX/PDF/XLSX/CSV reports can be saved into a write-allowed folder. Revoking access stops subsequent actions; it does not erase content you already imported, exported, or wrote to another app.

Worker and scheduled reports

Install independently on each PC and enter a separate approved API key/project configuration on each. Keys are never shared by the job queue. Choose the same approved ShareSync workspace and unique PC labels. Publish each identity in Worker, compare the displayed fingerprints using a trusted channel, and trust each peer explicitly on both PCs. Assign a remote job to one named Worker; other Workers cannot decrypt or run it.

Enable background jobs and optional start-at-sign-in on the Worker. Keep Windows signed in and awake with the workspace available. Private AI is a per-user background application, not a Windows service. Closing its window keeps it running when Worker is enabled; use the tray menu to pause or quit. Jobs may continue while Private AI is locked. Windows logoff, restart, sleep, missing credentials, or an unavailable work folder prevent unattended execution. An internal daily/weekday scheduler catches up once after a missed time, not once for every missed day. Do not clone the private data directory or copy schedules onto several PCs to run the same task.

Uncertain/interrupted jobs are not automatically generated again; review status before explicitly retrying. Successful generation with a failed export can be exported again without another provider generation. Ordinary analysis schedules use imported snapshots. Explicit local commands such as /unread, /calendar, and /report NAME use the permissions and reviewed workflows described in the hybrid guide. Final reports remain normal documents accessible from other authorized devices through the organization's ShareSync setup.

Retention, backup, and lock

Default retention is 90 days since last saved activity for local chats, working files, and completed jobs. Memory has separate expiry. Original source files and exported reports are not deleted. Failed cleanup is surfaced/deferred; synced backups and ShareSync version history have separate administrative retention. A local encrypted backup requires this Windows user's original DPAPI master key; a database alone is not a cross-PC backup. Set an optional app passphrase; maintain Windows screen locking, disk encryption, endpoint protection, and managed backups regardless.

Provider details

Local application safeguards

The renderer has sandboxing, context isolation, no Node integration, an exact trusted IPC sender check, restrictive CSP, and blocked remote renderer networking. Answer Markdown is sanitized and remote images are removed. Untrusted document/webpage text is marked as reference material, not instructions. The model has no app, folder, shell, or computer-control tools to execute a reference's malicious instructions.

Document extraction/export runs in a short-lived separate process with a memory ceiling and timeout; no key or vault handle is passed to it. Process isolation limits crashes, but is not a complete least-privilege OS sandbox: the utility process still runs under the Windows user's rights. Import only authorized documents. No macros, formulas, remote embedded images, or email attachments are executed. Office/PDF software used later to open exports is a separate security boundary.

Production Electron fuses disable RunAsNode, NODE_OPTIONS, Node CLI inspection, and loading the application from outside its ASAR. ASAR is packaging, not authenticated code signing. This build is unsigned and does not claim verified update authenticity or embedded-ASAR integrity enforcement. No automatic application updater is included. The optional model download verifies a pinned checksum. IT should sign and approve reviewed releases for broader deployment.

No cleartext application temp files are used for chat or imported content. DPAPI, memory, local file parsing, OS paging, Windows crash reports, other apps, and third-party sync retain their own behavior. An app lock hides interactive content but is not a separate cryptographic logoff; authorized background jobs may continue. Workstation protections remain essential.

Granting an Outlook/UI Automation read can make the selected local source visible to Private AI. It is not sent to OpenAI until the user explicitly uses it in chat and sends. Visible UI Automation text is best effort, not a guarantee that every provider's accessibility tree perfectly matches pixels. Permissions are checked again after asynchronous reads so locking/revoking prevents returning content. Write timeouts cannot guarantee the target app did nothing; inspect it before retrying. Version checks on local TXT/MD edits are optimistic, not a distributed ShareSync lock.

Existing users

The new application keeps data in %LOCALAPPDATA%\PrivateAI2. Older Python/v0.x directories are not modified or automatically imported. Keep the old version and its data until you have verified this build with synthetic work and exported any history you need. Import only approved documents into the new app. Do not solve an upgrade by deleting an old database.

Within v2, schema migrations run transactionally and preserve settings/history. A future unknown schema fails closed. For an upgrade, quit Private AI from the tray, make an organization-approved backup that preserves the original Windows profile/key, install the reviewed release, and run local checks. Local app backups preserve encrypted database records but require the original DPAPI master file. They are not a turnkey cross-PC restore procedure.

Installer and portable variants share the same local profile. Do not run both to create independent workers. If moving the portable application, reconnect Chrome afterward and update Chrome's loaded extension location. Keep the entire runtime folder together.

Disable redundant old scheduled jobs/Workers only after verifying the replacement. Private AI does not modify or turn off your previous installation. Each new Worker gets its own identity and explicit peer trust. Never sync or clone the PrivateAI2 private directory between active PCs.

Evaluation build, 11 September 2026. Windows binaries were cross-packaged on Linux and have not been executed on a real Windows PC here.

Completed evidence

They cover prior startup/file-handle and key-preservation bugs, encrypted records, permissions, retention, document processing, API behavior, Worker handoffs, four processing modes, Local Only network guards, memory refusal/unloading, usage estimates, messaging authorization/deduplication/uncertain delivery, background permission isolation, calendar overlaps, and per-task forwarding.

  • The pinned Qwen3-4B Q4_K_M GGUF completed real CPU inference through the local runtime on Linux with zero OpenAI calls. Runtime and model downloads were verified against pinned SHA-256 checksums. This is not a laptop speed benchmark.
  • The .NET Windows helper compiled successfully as a self-contained x64 application.
  • Packaging checks compare bundled code and extension files against source, inspect PE architecture, native dependencies, inference runtime, and Electron security fuses. Installer integrity and ZIP checks accompany the final downloads.

Validation logs are included in each download's Validation folder. Tests use synthetic content; no live mailbox, WhatsApp account, or reporting site was accessed.

Required on-PC acceptance

  1. With synthetic data and your usual Windows account, close all Private AI processes and run the new installer over the existing installation. Confirm prior settings and chat history remain, and run Settings → Run local checks. Do not delete the encrypted data folder to troubleshoot.
  2. Download/select the optional model. Try local arithmetic and a short attached-text summary in Local Only. Confirm no OpenAI calls appear. Test loading/unloading on the laptop and normal responsiveness.
  3. If cloud use is authorized, verify your existing key, approved settings, and a synthetic API call. Check actual token counts and configured price estimates.
  4. Check permission-controlled classic Outlook reads and calendar output. Confirm overlapping appointments against Outlook.
  5. Pair your own WhatsApp group with synthetic content, verified sender IDs, and the PC command code. Test new-message intake, a completion reply, conversation changes, sign-out, and Disable. Windows intake may expose insufficient stable identifiers; replies require the Web fallback. Native-only sending and attachments are not implemented.
  6. Configure and validate each website's exact report workflow. Confirm downloads reach the chosen ShareSync report folder. Test temporary ShareSync unavailability.
  7. Leave Worker running through a full workday, including scheduled tasks, model idle unloading, messaging interruptions, and recovery after Windows sign-in.
  8. Evaluate portable operation separately using the same account; run only one app copy at a time.

Until these checks succeed, the full upgrade plan is not fully accepted. This package does not certify HIPAA compliance. See HYBRID_UPGRADE.md for the precise implemented behavior and remaining feature limits.

Remote commands in 2.1.0

The optional Messaging bridge is now implemented as an experimental Windows/Web adapter. See HYBRID_UPGRADE.md for setup, permission checks, privacy warnings, and remaining limits.

Only new messages from approved stable sender IDs in the verified group, beginning with the configured prefix and this PC's command code, are accepted. Ordinary conversation and previously visible messages are ignored. Polling consumes no AI tokens. Local commands stay local; reasoning follows the selected processing mode and cloud permissions.

Completion/failure and optional started notices return through the WhatsApp Web connection. Response text needs a separate permission. Windows-app intake requires stable accessibility identifiers; native-only sending and attachments are not implemented. Documents stay in the approved report folder. Uncertain delivery disables the bridge without retrying.

This is a UI-based integration, not the official WhatsApp Business API. Live account pairing/delivery, platform eligibility, and the organization's approval of the channel remain to be checked. A group title alone never authorizes a task. The app does not claim that disappearing messages or encryption establish HIPAA suitability.

Outlook message/calendar reading and reviewed drafts remain available in Apps. Monitoring emails to yourself as a remote-command channel is not included in this hybrid release.
